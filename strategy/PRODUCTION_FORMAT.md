# Production Format

Sidequest should be intentionally cheap to produce. The idea and writing are the product; editing supports them.

## Default workflow

1. Find a strong, relevant idea.
2. Research the topic deeply enough to avoid vague self-help commentary.
3. Build a clear causal spine with but/therefore progression.
4. Write a concise, human script.
5. Record narration.
6. Place calm Minecraft gameplay underneath as the visual bed.
7. Add only essential editorial graphics.
8. Publish quickly and learn from topic/packaging performance.

## Visual rules

Minecraft footage:
- calm and readable
- continuous enough to hold attention
- not hyperactive parkour unless a test proves it performs better
- does not need to semantically match the narration

Graphics should be sparse and reusable:
- big number cards
- short comparison cards
- simple charts
- screenshots / source snippets
- short section labels
- occasional vintage newspaper-style illustrations

Brand graphics use:
- Crimson Pro
- off-white paper
- black / charcoal
- bright red accent
- vintage newspaper / editorial framing

## Editing philosophy

Do not source B-roll for every sentence.
Do not add transitions or sound effects merely because the frame has been static for a few seconds.
Do not create elaborate motion graphics when a number or sentence on screen is enough.

The production advantage comes from high topic throughput. A failed topic should cost very little editing time.

## Effort priority

Approximate priority order:
1. Topic / title / thumbnail concept
2. Research
3. Script
4. Narration
5. Editing

Minimal editing cannot mean minimal thinking.
